## Security review findings

The focused review found one authorization-order defect in Builder generation: a signed-in non-admin could trigger a model call for another app before version persistence rejected the request. The route now checks app ownership/administrator access first, and the regression test verifies the provider is not invoked. No exploitable critical/high application path was identified in the focused review. Separately, npm audit continues to flag the transitive `picomatch` package; current bundle traces and import-path review found its vulnerable matcher code is not included or invoked by production request handlers. Recheck this assessment when the upstream patch is released and whenever Next/Sentry configuration changes. This was not a full penetration test, and hosted security behavior remains unverified. |

Request IDs accept only bounded safe characters, are included with platform error logs, and are returned on those API errors. Email capture logs contain event/transport labels only. The Sentry scrubber removes request environment, response headers/cookies, trace attributes, arbitrary contexts, exception mechanism data, stack-frame variables, performance spans, arbitrary tags, and interpolated log parameters; it removes query/fragment information from request URLs and redacts invitation tokens in paths. Its focused test confirms private prompt text, auth headers/cookies, URL attributes, device identifiers, exception variables, tokens, account IDs, and learner email are absent from the scrubbed event. No passwords, action URLs, invitation tokens, project prompts, API keys, or database credentials were added to logs or evidence. Hosted Vercel logs verified safe correlation for readiness and a controlled authorization rejection; live Sentry receipt and durable alerting remain unverified.
