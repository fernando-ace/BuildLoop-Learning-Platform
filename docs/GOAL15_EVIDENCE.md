## Security review findings

The focused review found one authorization-order defect in Builder generation: a signed-in non-admin could trigger a model call for another app before version persistence rejected the request. The route now checks app ownership/administrator access first, and the regression test verifies the provider is not invoked. No critical/high defect remains known from this focused review. It was not a full penetration test, and hosted security behavior remains unverified.

Request IDs accept only bounded safe characters, are included with platform error logs, and are returned on those API errors. Email capture logs contain event/transport labels only. The Sentry scrubber drops request environment data and interpolated log parameters; it removes query/fragment information from request URLs and redacts invitation tokens in paths. Its focused test confirms private prompt text, auth headers, tokens, and learner email are absent from the scrubbed event. No passwords, action URLs, invitation tokens, project prompts, API keys, or database credentials were added to logs or evidence. Live Sentry receipt and hosted Vercel log visibility remain unverified.
